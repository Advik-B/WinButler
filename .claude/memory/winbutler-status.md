WinButler is an Avalonia 12 / .NET 10 / CommunityToolkit.Mvvm Windows disk cleaner. Motivation: the C drive is critically full (~16.8 GB free of ~237 GB; D: and S: have far more).

**v1 — DONE (2026-06-30):** scan + dashboard + dry-run + three cleaners.
- `Services/`: `IScanner` (+ `ElectronLeftoverScanner`, `TempScanner`, `CacheScanner`), `ICleaner`/`Cleaner` (dry-run chokepoint + hybrid delete), `DirectorySizeCalculator`, `RecycleBin` (SHFileOperation P/Invoke), `SizeFormatter`.
- Dry-run defaults ON and is a true no-op (returns before any FS mutation). Hybrid delete: `RiskLevel.Safe` → permanent; `Caution`/`Risky` → Recycle Bin.
- Electron detector keys on `app-*` + sibling `Update.exe` and numeric `System.Version` compare (NOT bare version dirs — that would nuke Chrome/Edge component dirs). Verified: flags GitHubDesktop app-3.5.11/3.5.12, keeps app-3.6.1.
- `app.manifest` requests `requireAdministrator`. User runs Claude Code as admin (no UAC babysitting needed).

**v3 — DONE (2026-06-30): "Disk Usage" tab — a real WizTree-like MFT scanner.**
- **`Services/Mft/`** (all `Span`/`BinaryPrimitives`, no `AllowUnsafeBlocks`): `NtfsNative` (raw `\\.\C:` handle, `FSCTL_GET_NTFS_VOLUME_DATA`, cluster-aligned `ReadFile`; mirrors `Junction.cs` P/Invoke style). `MftReader` reads the whole `$MFT` and parses every FILE record — USA fix-up (mandatory), `$FILE_NAME`/`$STANDARD_INFORMATION`/`$DATA` attributes, data-run decoder for record 0's own location. Output = flat `MftEntry[]` indexed by record#. `MftTreeBuilder` → aggregated `DiskNode` tree. `RecursiveWalkScanner` = non-NTFS fallback (same `DiskNode` shape). `DiskScanService` = façade (MFT for NTFS roots; re-roots tree at a subfolder; walk fallback; `GetScannableDrives()`).
- **Three correctness fixes found via headless cross-check vs a recursive walk (which == PowerShell `Measure-Object Length` byte-for-byte):** (1) skip extension records (`BaseFileRecordSegment != 0`) or fragmented files double-count; (2) **aggregation must propagate each node's INTRINSIC size from `entries[i].RealSize`, NOT the mutating `n.SizeBytes`** — a dir's SizeBytes has already accumulated children by climb time → 2.9 GB phantom over-count; (3) recover `$ATTRIBUTE_LIST`-evicted `$DATA` (VCN-0 size from the extension record, credited to base) or big fragmented files (Edge installers) show 0 bytes. After fixes: every shared path matches the walk EXACTLY; the only diff is hardlink duplicate-names. **Hardlinks are counted once per MFT record (per-record), so totals read a bit below WizTree's per-name counting — documented, by design.** Verified live: C: = 216.5 GB / 1.4M files.
- **UI is a `ListBox`, NOT TreeDataGrid.** `Avalonia.Controls.TreeDataGrid` 11.x AND 12.x are now flagged **commercial** by Avalonia 12's licensing MSBuild targets (`AVLIC0001`) → unusable without a paid key. Pivoted to a free, virtualized `ListBox` of flattened visible rows (`ViewModels/DiskRowViewModel` w/ Depth indent + ▸/▾ expander; `DiskScannerPageViewModel` manages expand/collapse splice + Size/Allocated/Name sort) — this is how WizTree itself renders, keeps numeric columns aligned. Plus `Controls/TreemapControl` (custom `Control.Render`, squarified treemap, FNV-hash hue, hover tooltip, click→`NodeInvoked`→re-root). Page wired as nav `Tag="disk"` + `MainWindowViewModel.DiskPage`.

**Headless UI test suite — DONE (2026-07-02): answered "why not use Avalonia's automated tests?"**
- Avalonia *does* have `Avalonia.Headless` (+ `Avalonia.Headless.XUnit`) — boots the real `App` on a windowless backend, `[AvaloniaFact]` bodies run on the UI thread. It's a **complement, not a replacement** for `tools/ui-harness/`: headless is a different renderer than the on-screen compositor (can't verify design fidelity), and the real elevated end-to-end app (MFT `$MFT` read + junctions) can't run headless. One code change: `ITestOutputHelper` moved from `Xunit.Abstractions` → `Xunit` (`MftReaderTests`). Added `<NoWarn>xUnit1051</NoWarn>` (v3 analyzer flags token-less I/O overloads the service tests use on purpose).
